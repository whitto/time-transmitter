# RadioClock V4.13 — Arduino source

Open `RadioClock_V4_13.ino` in Arduino IDE **2.3.4**. Keep this entire 11-file folder together: the sketch, all eight companion headers, `partitions.csv` and this README. The headers are `RadioBleArbiter.h`, `RadioBleScanControl.h`, `CasioBxProtocol.h`, `CasioWatchSettings.h`, `CasioWatchBattery.h`, `BtSyncLed.h`, `BtSyncHistory.h` and `RadioWifiAccessWindow.h`. No separate UI upload is needed; the web interface is embedded in the sketch.

Install **esp32 by Espressif Systems 3.3.12**, **NimBLE-Arduino 2.5.1** and **ArduinoJson 6.21.5**. For the user's classic 4 MB Node32 / Node32s board, choose **Node32s**, **40 MHz** flash and **No OTA (Large APP)**. ESP32 Dev Module with **4MB** and **Huge APP** is also supported. The supplied partition table defines the existing 3 MB application layout. The default small application partition is insufficient. Routine uploads do not require erasing all flash; erasing removes saved settings.

V4.13 changes the blue GPIO2 LED to a Bluetooth sync indicator. With **Settings → Enable blue ESP32 BT sync indicator** On, it flashes only during an actual connection/time-sync transaction, remains solid for 24 hours after successful TIME delivery, and turns off after an actual failed BT transaction. Passive listening, Wi-Fi and JJY/LF never make it flash; an existing solid success indication continues during LF. The master Off setting keeps it dark and preserves existing saved Off choices.

**Watch (BLE) → Last watch result → Save BT sync status to flash** is On by default. It immediately saves the first successful sync each Brisbane calendar day as a compact validated snapshot: UTC success timestamps and watch/profile identity, the daily quota, and four Bluetooth diagnostic counters. There are no logs, font results, battery readings or error strings in the snapshot. Later successes/failures remain in RAM; reboot restores the first saved daily snapshot and may forget a later failure. Profile completion is restored only for the matching watch binding. Off disables history writes/restoration and invalidates the old snapshot for later re-enabling. Toggling or rebooting does not reset the saved daily quota. Required configuration changes, including a new watch binding, still save normally. Routine time syncs no longer save the configuration file merely to record history.

The included V4.13 partition table removes the optional SDK flash core-dump partition to prevent panic logs being stored in flash. Application and LittleFS addresses/sizes are unchanged; the final 64 KB is unused. The SDK may print **“No core dump partition found!”** at boot; this is expected with flash crash storage omitted and does not mean the application failed. Serial panic/backtrace diagnostics remain available.

**Settings → Daily Wi-Fi access** adds independent start/end times and timezone for recurring web access. It defaults disabled, with **18:00–20:00 Australia/Brisbane** selected. Enabling saves automatically and selects Power-save; save time/timezone edits together using the schedule button. Overnight periods work; equal start/end times are rejected. Always on overrides the window. Setup AP, startup/recovery access and existing brief NTP wakeups remain available outside it. The Wi-Fi status tile is green for a station connection and red for AP mode; the radio tile is green during LF transmission and red while idle.

The existing GW-BX5600 battery estimate runs during Bluetooth sync before the SP/time handshake. It shows the selected watch's last estimate on **Watch (BLE)** and the overview's top **Watch** card. The percentage is calibrated in 10% steps. The battery reply wait is limited to 1.5 seconds; a battery-only failure does not prevent a time attempt. Invalid or missing readings show unavailable, never a fabricated 0%.

Battery readings are kept per watch in RAM, with the reading date/time in the Bluetooth timezone and offset. They clear on reboot, and a newly paired watch cannot inherit another watch's estimate. Other watch protocols have no validated battery calibration and show unavailable. This feature adds no flash writes.

The V4.11 host-serialized scan correction and optional 12-/17-byte font transaction remain. Font work and readback precede the freshly sampled final time. BT packet protocols, LF timing, working Wi-Fi/AP/NTP connection helpers, independent timezones, recurring schedules and the eight-item sidebar are preserved. V4.13 passed 37 Python host cases, UI/browser and native packet/stress checks, history sanitizers and the pinned Node32s compile. The build uses 1,426,872 bytes of program storage and 62,536 bytes of global RAM. Physical ESP32/watch acceptance remains required; no hardware test was performed in the cloud.
