# RadioClock V4.14 — Arduino source

Open `RadioClock_V4_14.ino` in Arduino IDE **2.3.4**. Keep this entire 11-file folder together: the sketch, all eight companion headers, `partitions.csv` and this README. The headers are `RadioBleArbiter.h`, `RadioBleScanControl.h`, `CasioBxProtocol.h`, `CasioWatchSettings.h`, `CasioWatchBattery.h`, `BtSyncLed.h`, `BtSyncHistory.h` and `RadioWifiAccessWindow.h`. No separate UI upload is needed; the web interface is embedded in the sketch.

Also install the included **RadioCrashDumpGate 1.0.0** source library. Copy the separate `RadioCrashDumpGate` folder into your Arduino sketchbook's `libraries` directory and restart the IDE. The full repository stores it under `libraries/RadioCrashDumpGate`; the Arduino-only ZIP includes it beside the sketch folder. Alternatively, download <https://github.com/whitto/time-transmitter/archive/refs/tags/crash-gate-v1.0.0.zip> and choose **Sketch → Include Library → Add .ZIP Library**. Keep all five files, including `library.properties`, `src/` and `src/esp32/README.md`, together. A missing `RadioCrashDumpGate.h` indicates the library is not installed; missing linker metadata deliberately fails the build. The cloud compile script installs it automatically. This helper is validated for classic ESP32; other MCU targets require their own linker metadata and validation.

Install **esp32 by Espressif Systems 3.3.12**, **NimBLE-Arduino 2.5.1** and **ArduinoJson 6.21.5**. For the user's classic 4 MB Node32 / Node32s board, choose **Node32s**, **40 MHz** flash and **No OTA (Large APP)**. ESP32 Dev Module with **4MB** and **Huge APP** is also supported. The supplied partition table defines the existing 3 MB application layout. The default small application partition is insufficient. Routine uploads do not require erasing all flash; erasing removes saved settings.

V4.14 adds **Settings → Crash dumps → Save crash dumps to flash**, default Off. Off blocks new diagnostic dumps; On allows the SDK to store one only after a panic. The saved toggle survives reboot, but the gate stays Off during early startup before saved configuration is loaded. Ordinary serial logs are not written to flash. Switching Off does not erase an existing dump, and switching On does not create one immediately. Enabled crash dumps have no once-per-day quota; they are separate from the existing daily BT snapshot. Serial panic/backtrace output remains available. Unsupported cores/builds show Unavailable.

The included partition table restores the dedicated 64 KB SDK core-dump partition omitted in V4.13. Application and LittleFS addresses/sizes are unchanged. The required helper library supplies the linker flag that gates the SDK panic writer; use the included library and partition table together.

The blue GPIO2 LED retains V4.13's Bluetooth sync indication. With **Settings → Enable blue ESP32 BT sync indicator** On, it flashes only during an actual connection/time-sync transaction, remains solid for 24 hours after successful TIME delivery, and turns off after an actual failed BT transaction. Passive listening, Wi-Fi and JJY/LF never make it flash; an existing solid success indication continues during LF. The master Off setting keeps it dark and preserves existing saved Off choices.

**Watch (BLE) → Last watch result → Save BT sync status to flash** is On by default. It immediately saves the first successful sync each Brisbane calendar day as a compact validated snapshot: UTC success timestamps and watch/profile identity, the daily quota, and four Bluetooth diagnostic counters. There are no logs, font results, battery readings or error strings in the snapshot. Later successes/failures remain in RAM; reboot restores the first saved daily snapshot and may forget a later failure. Profile completion is restored only for the matching watch binding. Off disables history writes/restoration and invalidates the old snapshot for later re-enabling. Toggling or rebooting does not reset the saved daily quota. Required configuration changes, including a new watch binding, still save normally. Routine time syncs no longer save the configuration file merely to record history.

**Settings → Daily Wi-Fi access** adds independent start/end times and timezone for recurring web access. It defaults disabled, with **18:00–20:00 Australia/Brisbane** selected. Enabling saves automatically and selects Power-save; save time/timezone edits together using the schedule button. Overnight periods work; equal start/end times are rejected. Always on overrides the window. Setup AP, startup/recovery access and existing brief NTP wakeups remain available outside it. The Wi-Fi status tile is green for a station connection and red for AP mode; the radio tile is green during LF transmission and red while idle.

The existing GW-BX5600 battery estimate runs during Bluetooth sync before the SP/time handshake. It shows the selected watch's last estimate on **Watch (BLE)** and the overview's top **Watch** card. The percentage is calibrated in 10% steps. The battery reply wait is limited to 1.5 seconds; a battery-only failure does not prevent a time attempt. Invalid or missing readings show unavailable, never a fabricated 0%.

Battery readings are kept per watch in RAM, with the reading date/time in the Bluetooth timezone and offset. They clear on reboot, and a newly paired watch cannot inherit another watch's estimate. Other watch protocols have no validated battery calibration and show unavailable. This feature adds no flash writes.

The V4.11 host-serialized scan correction and optional 12-/17-byte font transaction remain. Font work and readback precede the freshly sampled final time. BT packet protocols, LF timing, working Wi-Fi/AP/NTP connection helpers, independent timezones, recurring schedules and the eight-item sidebar are preserved. V4.14 passed 42 host cases, UI/browser checks, native packet/stress tests and the Node32s compile, using 1,429,192 bytes of program storage and 62,536 bytes of global RAM. Actual release-ELF inspection verified SDK panic dispatch through the IRAM gate, the aligned DRAM flag, the Off return and On delegation. The image checksum/hash are valid. Physical ESP32/watch acceptance remains required; no hardware test was performed in the cloud. The full repository's `docs/LONG_RUN_RELIABILITY_REVIEW.md` records remaining reliability findings and recommendations; this release does not silently fix them.
