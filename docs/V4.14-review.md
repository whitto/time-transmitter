# RadioClock V4.14 — optional crash dumps

V4.14 adds **Settings → Crash dumps → Save crash dumps to flash**, default Off, and includes a read-only [long-run reliability review](LONG_RUN_RELIABILITY_REVIEW.md). The toggle persists required configuration; it does not add continuous flash logging. Existing BT/LF protocols, LED/history behavior and Wi-Fi scheduling remain unchanged. Review findings are recommendations, not unrequested fixes in this release.

Active sketch: `firmware/RadioClock_V4_14/RadioClock_V4_14.ino`. Dependencies remain **Arduino-ESP32 3.3.12 / ESP-IDF 5.5.5**, **NimBLE-Arduino 2.5.1** and **ArduinoJson 6.21.5**. Classic ESP32 Node32s / ESP32 Dev Module is the release target.

## User-visible behavior

The new saved toggle defaults Off for new and older configurations. Off blocks new SDK crash dumps; On permits a future panic to store a diagnostic dump. Normal serial panic/backtrace output remains available in both modes. Enabling does not create a dump immediately, and disabling does not erase a previously stored dump. The gate starts Off before saved configuration is loaded, including early boot.

Crash dumps are separate from the optional compact daily BT status snapshot. They have **no once-per-day quota when enabled**: another panic may cause another SDK dump write. Routine serial messages are not written to flash. The compiled backend availability is exposed to the UI; unsupported cores/builds show Unavailable and cannot enable the control. Saves are acknowledged only after durable settings storage; failure rolls back the requested setting and keeps the previous gate state.

V4.14 restores the dedicated **64 KB core-dump partition** omitted in V4.13. Application and LittleFS addresses/sizes remain unchanged. The partition table provides storage; the required helper controls whether the SDK writer is entered.

## Required source library

Install the included **RadioCrashDumpGate 1.0.0** folder in the Arduino sketchbook's `libraries` directory. Keep all five files, including `library.properties`, `src/RadioCrashDumpGate.h`, `src/RadioCrashDumpGate.cpp` and the textual `src/esp32/README.md` marker. The project's cloud build installs this source library automatically.

The library uses GNU `--wrap=esp_core_dump_write` through standard Arduino library metadata. The pinned Arduino builders apply the linker flag using `precompiled=true` mixed-library mode and the ESP32 target-directory marker while compiling the `.cpp` normally. **No compiled archive is shipped.** A retained `__real_esp_core_dump_write` reference deliberately makes a missing linker flag fail the build, avoiding an apparently working Off toggle with an unguarded SDK panic path.

The wrapper resides in IRAM and reads one aligned 32-bit atomic word in internal DRAM. Its Off branch returns without allocation, logging, filesystem calls or the SDK dump writer. On delegates to the unchanged SDK writer. The setting update runs in normal application context after configuration is loaded or committed; the panic path does not read LittleFS.

The SDK has no supported public runtime-disable API for this flash backend. This helper leaves the installed board package and SDK unchanged. The target metadata and panic call path must be revalidated when changing the MCU/core/toolchain.

## Validation

Targeted helper tests passed: Off/On dispatch, unsupported backend, AddressSanitizer/UndefinedBehaviorSanitizer and deliberate missing-linker failure. The actual extracted configuration test passed legacy-default Off, save/reboot, both toggle directions under temporary-open/short-write/rename faults and unsupported-backend rejection. A linked SDK probe showed the SDK panic handler calling the IRAM wrapper, the Off branch using an inline DRAM load without helper calls, and the On branch calling the real writer.

- `bash scripts/test.sh`: **42 Python host cases passed**, plus UI JavaScript handler checks, native BX captured/malformed-packet checks and existing 10,000-session concurrent RF/BLE arbiter stress.
- `node scripts/test-ui-browser.cjs`: passed default-Off rendering, toggle saves/reboot state, storage failure and stale-response behavior, unsupported state and existing UI regressions.
- Node32s compile passed with `esp32:esp32:node32s:PartitionScheme=no_ota,FlashFreq=40`: **1,429,192 / 2,097,152 bytes (68%)** program storage; **62,536 / 327,680 bytes (19%)** global RAM, leaving 265,144 bytes. The CLI reports board No OTA capacity; the sketch-local table retains the project's 3 MB app partition.
- Actual release-ELF verification confirmed SDK panic dispatch calls `__wrap_esp_core_dump_write` at **0x40081474**, its wrapper/literal pool are in IRAM, its aligned flag is internal DRAM at **0x3ffbf958**, the Off branch returns without SDK/helper calls and On calls the real writer at **0x4014aad4**. Retained ELF SHA256: `54b81b3d961e538b588bb5a67e948731369359704b9a2259311e58ca3f9a1fa3`.
- `scripts/validate-crash-gate-elf.py` is now mandatory after compile; validation cannot rely solely on header/API presence or the earlier SDK probe.
- ESP32 image checksum/hash are valid. Compiled table contains the unchanged 3 MB app/896 KB filesystem layout and restored 64 KB core-dump partition.
- Desktop/phone Settings screenshots were inspected against the approved mockup. The new card defaults Off and all eight labelled sidebar items remain.
- Scope audit confirmed **23 working functions and all eight companion headers byte-identical to V4.13**, including BT packets/results, RF timing/handshake, Wi-Fi/AP/NTP and daily status behavior. Changes are limited to the new gate, settings/API/UI/build wiring, partition row and version/documentation.

Evidence: [compile](build-evidence/v4.14/compile.txt), [host tests](build-evidence/v4.14/host-tests.txt), [browser checks](build-evidence/v4.14/browser-tests.txt), [actual gate disassembly/validation](build-evidence/v4.14/crash-gate-validation.json), [image validation](build-evidence/v4.14/image-info.txt), [scope audit](build-evidence/v4.14/scope-audit.json) and [desktop](build-evidence/v4.14/settings-desktop.png)/[phone](build-evidence/v4.14/settings-phone.png) renderings. ## Device acceptance

Check default Off after upgrading an older configuration, saved Off/On across reboot, and unchanged serial diagnostics. A controlled crash test on a spare/test device can verify no new dump write with Off and SDK dump storage with On, using the matching release ELF for decoding. Do not deliberately crash a device during a required transmission. Confirm that turning Off leaves an existing dump intact and that BT daily history, battery/font behavior, LED indication, Wi-Fi windows and RF priority remain as before. Normal uploads do not require erasing saved settings.

Years-long unattended operation is not established by these checks. The separate reliability report records confirmed problems and recommended follow-up approval/testing; V4.14 does not silently change those working paths.
