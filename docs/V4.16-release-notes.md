# V4.16 R1 — Bluetooth listening schedule fixes

Released 10 October 2026 (Australia/Brisbane).

## Bug fixes

- **An invalid automatic slot no longer consumes its daily occurrence.** Previously, opening an unpaired or protocol-mismatched slot recorded that day as attempted before listening began. Pairing the watch later during the same window could leave scheduled listening suppressed until the next day. Occurrences are now recorded only after the watch binding and listening window are valid. Invalid slots remain eligible after pairing and do not repeatedly interrupt Always Wait for a different paired watch.
- **Saved Bluetooth timezone/offset changes rearm automatic listening.** Previously, an existing window kept its old deadline, and a completed occurrence could remain suppressed after a civil-time change moved the slot into its window again. Successful saves now reset the four automatic occurrence/deferred markers and safely stop an active automatic window. The normal service loop opens the appropriate window using the new Bluetooth civil time and recalculates its remaining duration. A failed BT time-setting save restores the previous zone/offset and retains the automatic schedule state.

## Reliability and compatibility

BT time fields are validated together using checked request copies. A fixed rollback buffer and checked String capacity keep apply/rollback bounded. Changes are rejected while a Bluetooth transaction is busy. Existing grouped LF/Wi-Fi/BT settings requests retain their save paths; window rearming occurs only after the checked atomic configuration save succeeds.

Manual, Pair Watch and Always Wait retain their existing operation. RF keeps priority. LF timezone/offset/encoding, Bluetooth packets, font/battery handling, LEDs, RAM history and daily flash-snapshot policy are retained. No new background flash writes, log files, tasks or callback objects are added. Normal uploads preserve saved settings.

The UI changes only its version labels. The sketch begins with the latest changelog and retains prior notes and original credits. Scripts and existing test fixtures point to the new active sketch.

## Dependencies and installation

Dependencies are unchanged from V4.15 R4: Arduino-ESP32 **3.3.12**, ArduinoJson **6.21.5**, bundled **NimBLE-Arduino 2.5.1-radioclock.1**, **RadioCrashDumpGate 1.0.0** and **RadioBoundedWebServer 3.3.12-radioclock.1**. Keep all three source libraries installed.

Open `firmware/RadioClock_V4_16/RadioClock_V4_16.ino` from the full project, or `RadioClock_V4_16/RadioClock_V4_16.ino` from the Arduino archive. Keep the complete 15-file sketch folder together, including all twelve headers and `partitions.csv`. The Arduino archive includes the sketch and all three libraries; no compiled binaries are supplied.

## Review and validation status

A fresh independent **source-only embedded reliability review** was completed before publication. See [the V4.16 review](https://github.com/whitto/time-transmitter/blob/main/docs/V4.16-review.md).

**No additional tests, browser checks or compilation were performed for V4.16, as explicitly requested.** Earlier V4.15 checks and defect reproductions explain the changes; they are not validation results for the corrected version. Physical scheduled-sync acceptance remains pending. The cause of the reported 12:30/18:30 misses with an already-paired BX5600 and unchanged Brisbane settings is not confirmed. These two fixes do not enable or program automatic adjustment on the watch.
