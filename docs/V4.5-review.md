# RadioClock V4.5 review — 7 October 2026

V4.5 addresses the final review of V4.2. The active sketch is `firmware/RadioClock_V4_5/RadioClock_V4_5.ino`; earlier version folders remain historical source.

## Corrected behavior

- Successful SNTP updates adjust the next adaptive interval without restarting the client after every reply. Clock confidence keeps the initial 50 ppm estimate until an actual drift measurement exists; resynchronization accounts for baseline uncertainty and the holdover limit.
- Sydney's independent Bluetooth timezone changes daylight saving at the correct UTC instant.
- Accepted Bluetooth slot edits clear that slot's attempt state. Disabling an active slot stops its window. Partial LF overlaps are allowed, with RF retaining priority and Bluetooth resuming only within an eligible window.
- Recurring Bluetooth switches and slot edits save on change, survive power restarts, and remain independent of the LF schedule Save button. Every enabled slot repeats daily until disabled, including later slots for a watch that already synchronized that day. Occurrence tracking uses the scheduled date across midnight and New Year.
- Settings API success is returned only after the configuration is written and atomically renamed in LittleFS. Failed automatic-slot saves retain the prior setting and report an error. Boot-time overlap checks retain stored switches; RF keeps priority.
- Saved successful Bluetooth delivery status and its date/time survive reboot. Replacement pairing remains transactional.
- Adding or removing an LF schedule preserves other unsaved inputs. End-of-day midnight supports existing all-day schedules and validates missing times before sending a request.
- The unsupported destructive address-clearing UI uses the supported replacement-pairing flow.
- BPC's three 20-second blocks have distinct start codes and matching parity.
- The workflow regression restores its temporary Always Wait setting before subsequent cases.

## Validation

Required checks are `bash scripts/test.sh`, `bash scripts/compile.sh`, `node scripts/test-ui-browser.cjs`, and rendered browser checks against `ui/v32_ui_mockup.png`. Compile validation uses Arduino-ESP32 3.3.11, NimBLE-Arduino 2.5.1, ArduinoJson 6.21.5, and `esp32:esp32:esp32:FlashSize=4M,PartitionScheme=huge_app`.

All release checks passed on 7 October 2026:

- `bash scripts/test.sh`: embedded UI/version/partition validation, JavaScript handlers, nine Python host tests, the concurrent RF/BLE arbiter stress test, and Casio packet validation. Persistence tests run actual configuration and schedule HTTP routes with ArduinoJson serialization, simulated reboot loading, and refused flash writes.
- `bash scripts/compile.sh`: **1,389,432 / 3,145,728 bytes (44%)** of application flash; **61,672 / 327,680 bytes (18%)** of RAM, leaving **266,008 bytes** for local variables.
- `node scripts/test-ui-browser.cjs`: Chromium regressions for LF drafts and midnight ranges, automatic-switch autosave, stale polling, LF Save independence, failed-save rollback, replacement pairing, and saved delivery/later failure display. The fixture waits for asynchronous handlers to finish before asserting their results.
- Rendered desktop, laptop, tablet, phone and narrow layouts at widths **1536, 1024, 820, 390 and 320**: all eight labelled sidebar items and navigation routes remain present, with no horizontal page overflow or JavaScript errors. Desktop and phone screenshots were visually compared with the approved mockup. The dashboard preview was refreshed from V4.5 using sample data.
- Source audit against V4.2 confirms unchanged JJY/carrier power constants, RF task/timer/amplitude code, other existing LF encoders, RF/BLE shutdown and Casio time-write functions. BPC's block-code correction is the intended encoder change.

Logs, browser results, source hashes and the RF scope audit are in [`build-evidence/v4.5/`](build-evidence/v4.5/). Host mocks and browser checks verify code paths and UI behavior; they do not measure the physical RF waveform, flash hardware reliability or the watch display. Scheduled listening remains subject to RF priority and the paired watch advertising during its window.
