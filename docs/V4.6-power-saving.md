# ESP32 power-saving assessment for V4.6

The classic 4 MB ESP32 build uses Arduino-ESP32 3.3.11 and NimBLE-Arduino 2.5.1. The project must preserve the RF waveform, its NTP-based clock confidence, independent Bluetooth schedule timezone and user-selected continuous listening.

| Method | V4.6 behavior | Constraints |
| --- | --- | --- |
| Blue LED off | Saved switch in Settings | Leaves the external RF envelope indicator and waveform unchanged. |
| Wi-Fi modem power saving / radio off | Existing Network Scheduled/power-save option | Applies `WiFi.setSleep(true)` while connected and switches Wi-Fi off outside boot/pre-sync windows. Web access is unavailable while Wi-Fi is off. |
| Bluetooth controller off between windows | New Network switch | Uses confirmed NimBLE host/controller teardown, then reinitializes for an eligible scheduled window or explicit Pair/Sync request. Always Wait keeps it awake. |
| Idle loop yielding | Included when idle BT power saving is enabled | Loop yields 10 ms outside RF/watch activity; the independent high-priority RF task retains its 1 ms timing. This is not full-chip sleep and has no claimed current reduction. |
| Automatic CPU frequency scaling / light sleep | Not enabled | The pinned ESP32 SDK config has `CONFIG_PM_ENABLE` disabled. The current 1 kHz hardware timer/task also needs a coordinated suspend/wake design before full-chip sleep can be enabled. |
| Explicit light sleep | Possible future option | Requires pausing all communication and the RF timer, choosing the next wake deadline, resuming peripherals safely and checking clock confidence. Sleeping during Always Wait would miss watch requests. |
| Timer deep sleep | Possible future option | Wakes through `setup()` as a reboot. It needs RTC-retained wake planning, schedule/timezone/DST handling, clock/NTP recovery, configuration flushes and treatment of manual requests/web access. It cannot preserve continuous listening while asleep. |

For the available savings, select **Network → Wi-Fi power-save**, enable **Power down idle Bluetooth**, explicitly turn **Always Wait** off and optionally disable the blue LED. Keep the desired automatic BT times enabled; these settings do not turn daily schedules off. Pair Watch/Sync Now can wake Bluetooth whenever web access is available. Scheduled windows wake independently of HTTP. RF retains priority, including its reduced/zero-carrier envelope periods.

The Bluetooth shutdown uses [`NimBLEDevice::deinit(false)` in the pinned library](https://github.com/h2zero/NimBLE-Arduino/blob/2.5.1/src/NimBLEDevice.cpp), which retains objects for reuse. Ownership is released only after the host is uninitialized and Espressif reports the controller idle. Tests cover refused teardown, incomplete controller shutdown, manual wake, next-day recurrence and RF priority.

The deep-sleep comparison uses Espressif's [Arduino timer-wakeup example at 3.3.11](https://github.com/espressif/arduino-esp32/blob/3.3.11/libraries/ESP32/examples/DeepSleep/TimerWakeUp/TimerWakeUp.ino): it enables a timer wake and calls `esp_deep_sleep_start()`, with `setup()` running again after wake. It is not a drop-in change for a live LF/BT scheduler. The installed `esp32-libs/3.3.11/sdkconfig` confirms `CONFIG_PM_ENABLE` is not set and Bluetooth controller modem sleep is enabled.

Actual board current depends on the USB interface, regulator, power LED and transmitter circuit. No current measurement or battery-runtime claim is made by these host tests.
