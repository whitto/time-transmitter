# RadioClock V4.9 — cold setup boot fix

Active sketch: `firmware/RadioClock_V4_9/RadioClock_V4_9.ino`. Core: `esp32:esp32@3.3.12`, NimBLE-Arduino 2.5.1, ArduinoJson 6.21.5.

## Confirmed regression and correction

V4.8 added an unconditional `esp_sntp_stop()` to setup/AP startup before `WiFi.mode(WIFI_AP)` initializes TCP/IP. On a cold boot with no saved credentials, the SDK shutdown wrapper posts to the TCP/IP task's mailbox even though the client was never started. The reported `tcpip_callback ... Invalid mbox` assertion occurs at that point.

V4.9 guards all three NTP shutdown sites with `esp_sntp_enabled()`. The query safely reads SNTP state; it does not post to the TCP/IP task. An unstarted client is left alone, while an active client still shuts down for AP recovery, credential changes and Wi-Fi power saving.

Verified against [ESP-IDF v5.5.5's SNTP implementation](https://github.com/espressif/esp-idf/blob/v5.5.5/components/lwip/apps/sntp/sntp.c#L187) and the installed core 3.3.12 SDK library: the stop function calls `tcpip_callback`; the enabled query reads static state. Wi-Fi initialization starts the network subsystem later in the no-credentials boot path.

## Validation

The regression fixture now models an uninitialized TCP/IP mailbox. The reported cold AP path fails against V4.8 with the matching assertion and passes against V4.9. Tests also cover cold credential startup, stopping a never-started client, and all three shutdown paths with an active client, alongside the previous Wi-Fi/NTP recovery scenarios.

The ESP32 Dev Module build passes on core 3.3.12: 1,405,820 / 3,145,728 bytes flash (44%), 62,016 / 327,680 bytes RAM (18%). The Node32s build also passes with `esp32:esp32:node32s:PartitionScheme=no_ota,FlashFreq=40`: 1,405,820 / 2,097,152 bytes reported capacity (67%), 62,016 bytes RAM (18%); the supplied custom partition table remains unchanged. Both generated application images have valid checksums and validation hashes. All 16 Python host tests, packet fixtures, 10,000-session arbitration stress and UI/browser regressions pass. Five viewport widths, both themes and all routes pass layout checks; rendered overview reviewed against the approved mockup. Independent SDK/source review passes. Compile/host/browser, expected V4.8 regression failure and source-scope evidence is in `build-evidence/v4.9`. An exact normalized comparison permits only the three shutdown guards, version metadata and embedded UI version. RF, Bluetooth protocol, scheduling, persistence, partitions and UI layout are unchanged.

The two flash-write reductions remain unchecked in `NEXT_VERSION.md`, as requested. This release implements the boot correction only. Device boot/setup still needs confirmation on the user's hardware.
