# RadioClock V4.0 UI release — 6 October 2026

V4.0 implements the supplied `ui/v32_ui_mockup.png` dashboard design. It is a UI-only release; the working V3.5 firmware behavior is preserved.

## Changes

- Navy sidebar with Overview, Radio, Watch, Schedules, Network, Settings, Diagnostics and About navigation.
- Large station-clock banner, inline skyline illustration and five tinted live status tiles.
- Overview cards for transmission controls, active LF format/time, clock information, daily transmission schedules and Casio Bluetooth sync.
- Separate JJY/LF and Bluetooth time previews; successful BT delivery retains its date and time in the top Watch status and overview watch card.
- Existing actions and API request payloads retained. Full-time output, scheduled output, NTP sync and watch sync use their existing handlers.
- Responsive bottom navigation on phones, keyboard focus indicators, accessible control labels, and persistent light/dark theme.
- Icons and skyline are embedded SVG, with no external assets or font dependencies.

The supplied mockup includes controls that the firmware does not implement, such as named/weekend schedules and a separate master output switch. V4 presents the existing daily station/start/end fields and continuous-output preference accurately.

## Firmware scope verification

Compared with V3.5 on GitHub main (`2b8ad45d1554dd5fc48cc27b029915462c1f8339`), the sketch is byte-identical after excluding only:

1. Sketch filename comment and directory/filename rename.
2. `FIRMWARE_VERSION` changing from `V3.5` to `V4.0`.
3. Regenerated `INDEX_HTML_GZ` web-page bytes.

The normalized firmware is 188,510 bytes, SHA-256 `e0b90ddda86d0c7b3ca83852fcdea51b737fdee25b4cbc398ae7d651f5836980`.

`RadioBleArbiter.h`, `CasioBxProtocol.h` and `partitions.csv` are byte-identical. All 82 original UI IDs and their original control-handler attributes are retained. Existing API request functions are unchanged. Script/test path updates follow the versioned sketch rename; the assertions are retained.

Radio carrier/duty/envelope timing, JJY encoding, Bluetooth/GATT handling, schedule interpretation, timezone/offset calculations, persistent configuration and server endpoints have no implementation changes.

- `bash scripts/test.sh`: all seven existing checks pass, including browser handlers, embedded gzip, JavaScript syntax, unique DOM IDs, API routes, BLE lifecycle/workflow, RF handoff, Casio packets and concurrent RF/BLE ownership.
- Embedded page: 72,614 bytes HTML, 19,577 bytes gzip; 119 unique IDs; all nine UI API paths exist.
- Chromium with mocked APIs: desktop 1536px, phone 390px, tablet 820px and narrow phone 320px; no JavaScript errors or document/navigation horizontal overflow. Navigation, theme persistence, readable light-theme branding and overview sync requests verified.
