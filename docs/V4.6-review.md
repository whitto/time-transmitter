# RadioClock V4.6 — watch font and idle power saving

The active sketch is `firmware/RadioClock_V4_6/RadioClock_V4_6.ino`. V4.6 adds the watch font, power-saving, LED and default settings requested for this release.

- **Watch (BLE) → Apply watch font during BT sync** saves a choice per watch profile. On defaults to Standard (new font); Classic is also available. Off preserves the watch's font. Only positively identified GW-BX5600 watches receive the settings command.
- Font uses the basic-settings characteristic and header `0x13`, separate from time delivery and the SP city/DST handshake. Firmware reads the 17-byte settings, modifies only byte 8 bit `0x20`, writes them back and confirms the font bit by another read. Malformed packets are refused; all other settings/reserved bytes remain intact. Font failure is reported separately and does not erase acknowledged time delivery.
- **Network → Power down idle Bluetooth** shuts down the host/controller between eligible automatic windows and wakes for Pair Watch, Sync Now or an enabled scheduled occurrence. Always Wait takes precedence and the UI reports that it pauses controller savings. Shutdown failure retains ownership so RF cannot overlap a live controller. The option defaults Off and survives reboot.
- Existing Wi-Fi Scheduled/power-save mode remains available independently. Full-chip sleep is not enabled: see [the power-saving assessment](V4.6-power-saving.md).

- Off keeps the classic ESP32 onboard GPIO2 LED dark.
- On flashes during JJY/other LF transmission or Bluetooth connection/time synchronization. Wi-Fi connection, AP mode and idle watch listening keep it dark.
- The switch saves on change and survives power restarts. Older config files default to activity flashing. Failed flash writes report an error and retain the previous setting.
- A separate low-priority task drives the blue LED, so blocking Bluetooth writes do not stop the flashing. It does not drive the carrier or the external RF envelope LED. The C3 shared LED/envelope pin is excluded from activity control.
- V4.5 behavior and the approved eight-item sidebar remain in place.
- New or unset configurations default all four automatic BT slots and Always Wait to On. Explicit saved Off settings remain Off; pairing continues to require the user's Pair Watch action.

## Validation

Required release checks: `bash scripts/test.sh`, `bash scripts/compile.sh`, `node scripts/test-ui-browser.cjs`, rendered overview/Watch/Network/Settings review and an RF/Bluetooth source audit against V4.5.

The font reference is the actual encoder/decoder in [`izivkov/gshock-smart-sync-webapp` at `5b3ff83`](https://github.com/izivkov/gshock-smart-sync-webapp/blob/5b3ff83dbae43a7a526232e5f35de98425ca7ac8/src/api/io/SettingsIO.ts). `node scripts/check-font-reference.cjs /path/to/pinned-web-app` executes that encoder/decoder against the committed Classic/Standard packet fixtures and checks its characteristic UUID mapping. Firmware tests use those literal packets, run the actual post-time font function with transport failures/readback mismatch, and verify preservation of other bytes. This is validation against a working implementation, not a claim of testing on a physical watch.

All release checks passed:

- ESP32 compile (Arduino core 3.3.11, NimBLE 2.5.1, No OTA/huge_app): 1,400,644 of 3,145,728 bytes flash (44%); 61,688 of 327,680 bytes RAM (18%).
- Host suite: 15 Python tests, packet fixtures, UI handler checks and concurrent arbiter stress with 10,000 RF sessions passed. Tests cover persisted preferences, failed storage writes, font readback errors, time-success preservation and failed controller shutdown ownership.
- Chromium regression passed font selection/opt-out, reloads, storage rollback, LED stale-response protection, default schedules and existing sync/pair workflows.
- Rendered overview, Watch, Network and Settings reviewed against the approved mockup. All eight sidebar items remain; five viewport widths (320–1536 px), both themes and all routes pass geometry checks. A new power badge overflow at 320 px was corrected before release.
- Source comparison confirms RF carrier constants, RF encoders/timing, arbitration and standard time protocol unchanged from V4.5. BX5600 time delivery is unchanged except the font action after successful delivery.
- The actual pinned GitHub web app encoder/decoder and characteristic mapping match the committed font fixtures.

Logs, source hashes and scope audit are in [build-evidence/v4.6](build-evidence/v4.6). Physical LED brightness, watch display, controller restart on a real board, current consumption and RF waveform checks still need ESP32/watch hardware.
