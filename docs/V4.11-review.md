# RadioClock V4.11 — scan lifecycle and GW-BX5600 font correction

Source release **V4.11**. The checks below validate the source and cloud build; physical ESP32/watch acceptance remains outstanding.

Active sketch: `firmware/RadioClock_V4_11/RadioClock_V4_11.ino`. Dependencies: **Arduino-ESP32 3.3.12**, **NimBLE-Arduino 2.5.1**, **ArduinoJson 6.21.5**. Previous release: V4.10, commit `40f309b0ddfac04095ac58d6c821d9df4b26e67f`.

## Bluetooth scanning defect and correction

V4.10 restarts one-second scans from `loopTask` when NimBLE reports scanning inactive. That status can change before the host task finishes scan-completion and advertised-device cleanup. Starting/clearing results from another task during this interval can free data still in use by the host callback. Native reproduction using the installed NimBLE implementation exposes a use-after-free and a null pending-list-head read at offset `0x0c`.

The V4.11 correction in `RadioBleScanControl.h` serializes all scan start/stop operations with the NimBLE host event queue. This includes manual windows/retries, Always Wait, scheduled windows, connection cancellation and RF shutdown. It disables the independent scan-response timer with `setScanResponseTimeout(0)` while retaining active scanning and the existing one-second scan-completion fallback. Timed-out commands keep their event/state until host acknowledgement. RF shutdown requires coordinator quiescence; its event is released only after host deinit has stopped NimBLE, and later startup initializes fresh event state.

The user's latest V4.10 panic is Core 0 `LoadProhibited`, `PC=0x400ee979`, `EXCVADDR=0x0000000c`, with a backtrace strongly matching the scan waiting-list/completion code shape. The user's ELF hash `919c068de` differs from the retained cloud ELF, so this is not a definitive absolute-address decode. Their earlier RAM-PC `InstructionFetchError` has a corrupted backtrace; this release cannot promise to eliminate every cause of memory corruption. The 13:14 restart was an intentional user reset/power cycle. The 13:23 reboot is a confirmed panic.

Upstream NimBLE issue [1184](https://github.com/h2zero/NimBLE-Arduino/issues/1184) concerns a separate host-timer deinit defect. Its dependency correction is not applied by this project's scan fix or included in the pinned 2.5.1 release. Avoid claiming it is covered.

## Font packet and transaction correction

Actual GW-BX5600 captures contain 12-byte basic-settings replies and writes; the old helper accepts only 17 bytes. The correction accepts both observed formats, preserves the original length and unrelated bytes, and changes only byte 8's `0x20` font bit. Classic sets the bit; Standard clears it.

The optional read/change/readback transaction moves before the final TIME command. The watch can disconnect immediately after TIME acknowledgement during a D-button manual time correction; the user's example disconnected 73 ms after reported time delivery. The firmware calculates current time after the optional font work and sends TIME last. Font Off retains the existing time-only sequence. Font failure is reported separately from time-delivery success.

References: [gshock-smart-sync-webapp](https://github.com/izivkov/gshock-smart-sync-webapp), commit `5b3ff83dbae43a7a526232e5f35de98425ca7ac8`, and real captures in [gshock_api](https://github.com/izivkov/gshock_api), commit `ae817310dd9551d5e6e53ee61d89af4e8d954767`. The helper is independently implemented; original project credits remain.

- Browser/API regression: passed controls, persistence/failure behavior and all eight sidebar routes. Rendered desktop comparison retained the approved fixed sidebar, verified both GitHub links and found no horizontal overflow.
- Asset checks: 90,011-byte HTML, 23,841-byte gzip; round-trip exact; 145 unique IDs and 9 API routes.
- Source scope: scan coordinator/lifecycle, font packet/order/result reporting, version metadata, the two requested project links and documentation/tests. The working Wi-Fi/NTP, LF encoders/timing, timezones and configuration persistence remain unchanged.
- Physical ESP32/watch testing: **not performed in the cloud**. The watch's D-button session accepting the font transaction still needs user confirmation.
