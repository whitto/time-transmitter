# V4.14 build R2 — reliability corrections and release review

The user authorized all recommendations from the V4.14 long-run review and requires a reliability review before every future publication. R2 keeps firmware version **V4.14**, increments its build to **R2**, and publishes new immutable tags. Existing V4.14 R1 tags/review remain historical.

## Behavior changes

- Configuration and schedule saves are bounded, checked and read back before atomic replacement. Allocation/serialization/storage failures preserve the previous files. Failed config commits stop background retries until an explicit successful user save.
- Boot configuration parsing admits only bounded, structurally valid files. Corrupt records remain on flash and safe defaults provide setup access. Filesystem mount errors never automatically format. Settings allows an explicitly confirmed destructive reset only through a filesystem-fault setup AP.
- Saved station credentials retry automatically after outages while AP access remains available. Network startup and retry service return without connection/reply wait loops. Power-save Wi-Fi wakes before adaptive NTP trust deadlines independently of LF/BT/web access; startup access expires once across millis rollover.
- A pinned, source-only NimBLE 2.5.1-radioclock.1 fork includes the upstream host-timer shutdown correction and checked initialization allocations. The firmware rejects the plain library. BT deadlines request normal cancellation/disconnect, retain callback storage and gate RF during unresolved teardown.
- RF pause generations cannot apply after rejection/timeout. Temporary owners preserve intentional AP pause and check resume recovery. Timing/task/monitor initialization is checked; genuine timer progress is required. RAM-only progress/headroom monitoring forces the carrier off on fault and uses bounded recovery or a controlled restart for unrecoverable stalls.
- Diagnostics displays uptime as hours, minutes and seconds, retaining the 64-bit source counter.
- Common JSON responses use checked bounded storage; Diagnostics refreshes on demand. Diagnostic uptime uses 64-bit monotonic time. Clock confidence retains absolute drift uncertainty and rejects implausible SNTP replies before applying them.

No periodic maintenance reboot or flash log was introduced. Essential settings remain durable. Optional first-success-per-Brisbane-day BT retention and default-Off panic dumps retain their separately approved policies. BT packet formats, LF encoders, independent JJY/BT timezones, watch font/battery behavior and the eight-item sidebar remain.

## Build and installation

Classic ESP32 Node32s, 4 MB flash, Arduino-ESP32 **3.3.12**, **40 MHz / No OTA (Large APP)**, ArduinoJson **6.21.5**, included NimBLE-Arduino **2.5.1-radioclock.1** and RadioCrashDumpGate **1.0.0**. The sketch-local table retains the 3 MB app, 896 KB filesystem and 64 KB optional core-dump partition.

Keep the complete 14-file sketch folder and both included source libraries. Replace duplicate/plain NimBLE 2.5.1 installations; keep all crash-gate metadata, including its `src/esp32/README.md` marker. Cloud scripts verify/install the pinned sources. No compiled firmware/library binaries are distributed. The Arduino-only archive contains the sketch and both complete source-library folders.

## Regression and fault coverage

- `tests/test_storage_reliability.py`: production config/schedule saves, allocator failure/partial JSON, complete-format/line/file limits, exact readback, seven storage stages, repeated idle calls without further writes, legacy boot configs, confirmed mount recovery and ASan/UBSan with leak detection.
- `tests/test_nimble_pin.py` and `tests/test_ble_lifecycle.py`: source integrity, actual queued timer behavior, singleton/initialization failures, deadline/cancellation, safe ATT lifetime, callback quarantine and repeated host shutdown/restart. Existing scan coordinator tests and RF/BLE stress remain.
- `tests/test_network_reliability.py`, Wi-Fi/NTP recovery/access tests and clock tests: nonblocking association, outage/AP-plus-station recovery, adaptive trust wakes, retry bounds, startup rollover, signed drift reversal, implausible pre-commit reply rejection and 64-bit uptime.
- `tests/test_radio_reliability.py` and RF handoff tests: late/cancelled pause commands, independent ownership/resume, timer allocation and absent/stopped ticks, progress fault and recovery policy.
- `tests/test_json_writer.py`, UI script/browser checks: escaping/overflow, checked responses, settings rollback, on-demand diagnostics, fault-only destructive recovery and existing watch/LED/history/access behavior. Rendered desktop/phone/sidebar checks must match the approved mockup.
- Pinned Node32s compile, partition/image inspection and mandatory `scripts/validate-crash-gate-elf.py` prove the selected build still routes SDK panic writing through the IRAM gate and aligned DRAM flag. The release archive must download and match the tested source before success is reported.

## Final pre-publication review and evidence

The updated [long-run review](LONG_RUN_RELIABILITY_REVIEW.md) maps every original finding to its correction and regression. It examines bounded memory/stack usage, allocations, callbacks, task progress, deadlines/rollover, RF/BLE exclusion, network recovery, durable settings and flash-write frequency. An independent review also found and corrected the unbounded boot-config line-read path.

The independent pre-publication review found no unresolved blocking defect after the corrections above. The exact Node32s target compiled during integration; actual-ELF checks verified both the IRAM crash gate and SDK dispatch to the strong SNTP pre-commit hook. The final uptime-display asset is included in the post-publication build; final sizes and the matching ELF hash are reported in release notes. Browser and focused fault checks passed.

Following the user’s release order, the complete suite runs after source publication; its final results and any necessary subsequent revision are reported in the GitHub release notes. Review is required before publication, and test failures require a new immutable build revision. R1 evidence remains historical and must not be reused as R2 validation. No hardware soak was performed.

## Device acceptance and remaining limits

No ESP32/watch is attached to this cloud. Host injection and compile/ELF checks establish software behavior under the tested conditions, not real RF timing, radio reception, flash fault recovery, heap/stack margins or years without a reboot. Run the physical soak and fault checklist in the reliability report with the exact build. Unrecoverable progress faults deliberately permit a safe controlled restart; no periodic reboot is used as a reliability substitute. Serial/externally captured measurements stay outside flash.
