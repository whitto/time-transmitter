# RadioClock V4.15 build R1

V4.15 fixes all nine further reliability findings from the V4.14 R2 review. It also adds the selected watch's four most recent Bluetooth sync outcomes in RAM and shows uptime as hours, minutes and seconds in Overview and Diagnostics. The eight-page sidebar, LF encoder/timing, independent JJY/BT timezones and existing watch time/font/battery protocol are preserved.

## New features

- **Last four BT syncs:** Watch (BLE) shows successful and failed transactions for the selected watch, newest first, with date/time in the current Bluetooth timezone and offset. Each of the four watch profiles has its own fixed four-entry ring. Successful means the existing acknowledged TIME delivery; the watch display is not independently verified. An actual failure with an untrusted clock shows **Time unavailable**. Passive listening, a missing watch and RF-deferred work do not create failed entries. Failed replacement pairing preserves the old watch's list; a confirmed replacement starts a new list. The list uses 224 fixed RAM bytes, clears on restart and adds **no flash writes**. It is separate from the existing optional first-success-per-Brisbane-day saved snapshot.
- **Consistent uptime:** Overview and Diagnostics now use the same hours/minutes/seconds formatter, including hours beyond 24. The underlying 64-bit monotonic uptime is retained.

## Reliability fixes

1. **NTP acquisition and reacquisition:** an incorrect initial plausible clock anchor can recover through a bounded confirmation window. Initial acquisition and reacquisition require three consistent monotonic-projected replies spanning at least 30 seconds before time becomes trusted. Too-fast duplicates, inconsistent/malformed replies and expired candidates cannot establish trust. LF transmission and BT TIME delivery remain blocked while provisional.
2. **BLE shutdown progress:** scanner, client and controller shutdown share one retained 60-second recovery deadline, including scan-stop failures with no client and partial controller initialization. Retries or new work do not reset it. Pending callbacks and client storage retain their lifetimes, and RF remains gated until the controller is physically Off. Irrecoverable stalls use safe last-resort fault recovery with RF forced off; there are no periodic maintenance reboots.
3. **Bounded HTTP requests and responses:** the required source-pinned server admits at most 4096 body bytes before allocation, limits headers/lines and enforces one absolute ten-second receive budget across headers and body. Response headers/body share a five-second socket-write budget; partial progress cannot extend it. The unbounded SDK receive drain is removed. Checked argument decoding and bounded multipart parsing preserve the dashboard's FormData, URL-encoded forms and JSON. Ambiguous content lengths, transfer encoding and file/raw uploads are rejected.
4. **Final Bluetooth clock confidence:** active transactions cancel when confidence is lost. BX and standard/analogue paths recheck before sampling final TIME, and the common write path checks again before submission. Blocking ATT callbacks unwind through their normal completion/cancellation path rather than outliving stack storage.
5. **Timer recovery over a long service life:** the three-attempt recovery budget replenishes after 30 minutes of continuously qualified interrupt/radio-task/monitor progress. Brief requalification, stale progress and recurring faults cannot replenish it. Lifetime retry diagnostics saturate independently, so healthy operation can recover from later unrelated faults without creating an endless rapid retry loop.
6. **Strict saved settings and integrity:** all stored fields are validated as one bounded candidate before live settings change. A versioned CRC32 record detects content damage and truncation; strict integer/boolean/enum/timezone/MAC/calendar checks reject malformed values such as `630junk`. Checked String reserves protect application of the candidate. The version marker cannot collide with a supported legacy SSID. Valid legacy settings load without a boot/idle migration write and upgrade on the next actual settings or binding save. Corrupt files are retained for explicit recovery.
7. **Checked Wi-Fi power transitions:** requested power and observed driver state remain separate. Failed disconnect/Off operations expose a RAM fault and retry with bounded one-second-to-one-minute backoff. A still-connected station retains web/NTP service instead of becoming connected but unserviced. A new On window cancels pending shutdown; verified state clears the active fault.
8. **Adaptive NTP uncertainty recovery:** accepted short-interval replies accumulate against an independent drift anchor instead of resetting the measurement window. The adaptive interval can recover after a jitter sample while retaining conservative absolute uncertainty and holdover limits.
9. **SSID byte limits and safe credentials:** the UI and API enforce the ESP32 station's 32 UTF-8-byte SSID maximum. Checked copies stage both credentials and validate them before either live value changes, preserving previous credentials if a copy fails or the supplied password is invalid.

Diagnostics exposes NTP confirmation/reacquisition progress, requested/observed Wi-Fi power and RAM power faults, plus lifetime/current timer retry counts. Existing optional daily BT status retention, default-Off crash storage, blue LED behavior and explicit configuration-save durability remain unchanged. The new four-entry list is never written or restored, even when daily snapshot retention is enabled.

## Source downloads and installation

- [Full V4.15 R1 repository source ZIP](https://github.com/whitto/time-transmitter/archive/refs/tags/v4.15.zip)
- [Arduino sketch and all three required source libraries](https://github.com/whitto/time-transmitter/archive/refs/tags/arduino-v4.15.zip)

This is a **source-only** release; no compiled firmware is supplied. Open `firmware/RadioClock_V4_15/RadioClock_V4_15.ino` in the full repository, or the equivalent sketch folder in the Arduino archive. Keep the complete companion-header/partition folder together, including the new `BtRecentSyncs.h`. Use Arduino-ESP32 **3.3.12**, ArduinoJson **6.21.5**, and a suitable No OTA application partition for the classic 4 MB Node32s target. The existing sketch-local partition table is retained. Normal upgrades should preserve saved settings; routine flash erasure is not required.

Install all three included libraries into the Arduino sketchbook's `libraries` folder and restart Arduino IDE:

| Required library | Version | Library-only source ZIP |
| --- | --- | --- |
| RadioBoundedWebServer | **3.3.12-radioclock.1** — new in V4.15 | [webserver-v3.3.12-radio-v1](https://github.com/whitto/time-transmitter/archive/refs/tags/webserver-v3.3.12-radio-v1.zip) |
| NimBLE-Arduino | **2.5.1-radioclock.1** — existing patched version retained | [nimble-v2.5.1-radio-r2](https://github.com/whitto/time-transmitter/archive/refs/tags/nimble-v2.5.1-radio-r2.zip) |
| RadioCrashDumpGate | **1.0.0** — existing version retained | [crash-gate-v1.0.0](https://github.com/whitto/time-transmitter/archive/refs/tags/crash-gate-v1.0.0.zip) |

RadioBoundedWebServer is separately named, so the ordinary ESP32 board-core WebServer remains installed. It derives from Arduino-ESP32 3.3.12 WebServer at commit `94afccf35fb1e401facddbcf9e13bcf7c76a31d8`; original authors, LGPL 2.1-or-later notices and license are retained alongside upstream hashes, the project patch and an exact source manifest. Cloud tooling validates and installs the included source, preventing silent selection of the unchanged SDK parser. Remove duplicate/unpatched NimBLE installations so Arduino selects the included patched version. Keep the crash-gate library's linker metadata and marker files intact. All three packages contain source rather than compiled library archives; existing NimBLE/crash-gate tags are unchanged.

## Validation

**Passed before publication:** the independent embedded reliability review, targeted production-function fault regressions and source-pin checks. Focused runs cover malformed/slow/partial HTTP traffic, allocation failures, NTP anchor/jitter recovery, BLE shutdown and callback lifetimes, final TIME trust loss, timer fault budgets, Wi-Fi transition failures, strict storage integrity and legacy compatibility. New feature checks cover a million bounded ring inserts, actual sync-result/flash isolation, selected-profile races, restart behavior and long uptime. The bounded config/status route fixture repeats 80,000 responses without retained host allocation growth. Applicable native cases use ASan/UBSan/leak checks. See [the release review and retained evidence](https://github.com/whitto/time-transmitter/blob/v4.15/docs/V4.15-review.md).

**Passed after source publication:** the complete `scripts/test.sh` run on commit `ba3c30ac46cb975dcca909cd17cf7da2b4775d8d`: **77 unittest cases across 23 groups**, plus project/gzip/JavaScript/UI checks, native captured-packet checks and concurrent RF/BLE stress. ASan/UBSan/leak fixtures passed, including 80,000 bounded API responses without retained host allocation growth and one million fixed-ring inserts. The native arbiter completed 10,000 RF sessions and 9,446 modeled BLE sessions without overlap. The full Chromium regression suite and an additional real-browser check of four success/failure rows, unknown times, profile isolation, restart clearing and `72h 04m 09s` uptime passed on desktop and 390 px phone layouts. No correction revision was needed.

All five direct source ZIPs downloaded and matched their immutable tag trees byte-for-byte, with no compiled binaries. The Arduino package contains 526 files: the 15-file sketch and all three complete libraries. [Retained validation/download evidence](https://github.com/whitto/time-transmitter/tree/main/docs/build-evidence/v4.15).

**ESP32 compile omitted at the user’s request:** the active board compile was stopped. No board-build, program-size or ELF result is claimed for V4.15. No compiled firmware was published. Source was pushed and the release published before the full tests, as requested; existing version tags remain immutable.

No physical ESP32/watch is attached to the cloud environment. Real RF/BLE handoff, router/NTP outages, controller shutdown, interrupted storage operations, heap fragmentation, task-stack margins and prolonged device soak still need physical acceptance. The focused checks do not establish years of uninterrupted operation or make every SDK/application String copy allocation-free. The existing trusted-holdover policy remains: a pre-transmission Wi-Fi window does not force a fresh NTP reply before every LF session when already connected.
