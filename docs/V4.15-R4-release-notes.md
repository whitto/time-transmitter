# RadioClock V4.15 build R4

R4 fixes the false **Check timing** warning reported with 1,791,589,577 missed seconds after only nine minutes of uptime. The diagnostic counter previously counted the initial NTP clock jump as skipped scheduler seconds; deliberate pauses could also produce false counts and misleading worst-delay readings. This revision was requested directly as R4; previous published tags remain immutable.

## Changes in R4

- Count missed boundaries only during continuous, stable-clock active RF transmission. Startup acquisition, forward/backward clock corrections, deliberate pauses, faults, idle intervals and fresh RF starts establish a diagnostic baseline instead of counting a gap.
- Cross-check wall-clock progress against 64-bit monotonic time and mark NTP clock commits with diagnostic-only metadata. A sample overlapping a clock update cannot become a timing measurement. RF envelope timing, clock admission and actual clock-setting behavior are preserved.
- Record current/worst boundary delay only from qualified active RF samples. Real stable-clock delayed processing still produces diagnostics; counters saturate safely instead of wrapping.
- Keep all tracking in fixed RAM, owned by the radio task. No allocation, log storage or flash writes are added.
- Add newest-first release/change notes at the top of the Arduino sketch, including R4, R1 and the earlier V4.14 corrections. Version labels and build metadata now report **V4.15 R4**.

The System card continues to show Check timing when an actual cumulative missed-boundary count is above zero. It is a record since boot, not a calibrated RF edge measurement. Existing progress monitors independently handle actual timer/task stalls. The eight-page UI layout, LF encoders/carrier/envelope scheduling, RF/BLE exclusion, watch packet protocols, timezones, saved settings, blue LED, optional daily BT snapshot and crash-storage policies are retained.

## Retained from V4.15 R1

- Latest four successful/failed BT attempts per selected watch in a fixed 224-byte RAM history, newest first; clear on reboot/replacement with no extra flash saves. Overview and Diagnostics show uptime in hours/minutes/seconds.
- Three consistent NTP replies over at least 30 seconds for initial acquisition/reacquisition, with LF/BT withheld while provisional; aggregation of short drift samples restores adaptive intervals after jitter.
- Common bounded BLE shutdown progress, retained callback/client lifetime and final TIME clock-confidence checks.
- Qualified 30-minute health replenishment for the timer retry budget, separate from saturating lifetime counts.
- Strict, versioned CRC32 saved configuration with complete candidate validation; legacy migration only on actual saves and preserved corrupt files.
- Checked desired/observed Wi-Fi Off transitions, RAM faults and bounded retry backoff while retaining access/NTP if still connected.
- 32-byte UTF-8 SSID checks and staged credential copies before live settings change.
- Required source-pinned HTTP server with request/response size, allocation and absolute-time bounds; dashboard text forms and JSON remain supported.
