# RadioClock V4.10 — setup AP startup correction

Active sketch: `firmware/RadioClock_V4_10/RadioClock_V4_10.ino`. Toolchain: **esp32:esp32@3.3.12**, NimBLE-Arduino **2.5.1**, ArduinoJson **6.21.5**.

## Confirmed defects and correction

The reported V4.9 boot reaches the web server and radio scheduler, but its AP is absent from the client's Wi-Fi list. Two confirmed source defects make that log unreliable:

- `startAPMode()` reads the AP network-interface MAC before the asynchronous `WIFI_EVENT_AP_START` handler fills it. IDF can return a successful read containing zeros, producing `RadioStation_000000` without a MAC error. This explains the suffix; it does not itself explain absent beacons.
- Both `WiFi.mode(WIFI_AP)` and `WiFi.softAP()` return values were ignored. The configured default IP was printed as successful startup even after a driver or AP configuration failure.

V4.10 derives the SSID through checked `esp_read_mac(..., ESP_MAC_WIFI_SOFTAP)`, independent of AP-start events. A read error, all-zero MAC or multicast MAC uses the named `RadioStation_Setup` fallback. AP startup explicitly uses channel 1, visible SSID, the existing password `12345678` and four clients. Driver mode, AP creation, the AP-start event flag and a nonzero local IP must succeed before the success message and web server startup.

Failed startup leaves RF paused and reports the failing stage in serial. The loop retries after five seconds, requesting Wi-Fi OFF before another AP attempt. This is a timed startup retry; the core may short-circuit OFF when the earlier driver start failed, so complete low-level reinitialization is not guaranteed. A healthy AP is never cycled by this recovery path. Credential connection and successful STA handover cancel pending AP retries. Existing SNTP shutdown guards preserve the V4.9 cold-network assertion fix.

Implementation reviewed against the installed core 3.3.12 [`WiFiGeneric.cpp`](https://github.com/espressif/arduino-esp32/blob/3.3.12/libraries/WiFi/src/WiFiGeneric.cpp), [`AP.cpp`](https://github.com/espressif/arduino-esp32/blob/3.3.12/libraries/WiFi/src/AP.cpp), [`NetworkInterface.cpp`](https://github.com/espressif/arduino-esp32/blob/3.3.12/libraries/Network/src/NetworkInterface.cpp), and the official [`WiFiAccessPoint` example](https://github.com/espressif/arduino-esp32/blob/3.3.12/libraries/WiFi/examples/WiFiAccessPoint/WiFiAccessPoint.ino). IDF v5.5.5's AP-start handling populates the netif MAC asynchronously.

If AP initialization fails, capture its new `ERROR:` lines. If confirmed startup is logged but the network remains absent, check another nearby 2.4 GHz client and supply the full serial output for hardware/coexistence diagnosis.
